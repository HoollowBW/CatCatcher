## 怎么读这份记录

每一轮都是同一条链路：**用户提需求 → 助手先说改哪几个文件 → 改 → 跑验证（selftest / solvecheck / 真机渲染）→ 贴结果**。重点看三类地方：

1. **规则先定稿再实现**：涉及玩法的回合里，助手先改 `ARCHITECTURE.md` 第 5 节，再动 `Core/`。
2. **验证卡退出码**：`selftest` 131 条断言、`solvecheck` 量关卡难度，工具结果的结尾常能看到 `passed, 0 failed` 与难度梯度。
3. **探针定位**：凡是"看起来是手感问题"的回合，都是先写 `tests/_xxx.gd` 喂真实输入复现，改完再删。
